NadaTrade Documentation

Config Keys

This document lists every configuration key recognized by NadaTrade’s TOML config file. The authoritative source is crates/nadatrade-bin/src/config.rs.

All keys are optional unless marked required.

[server]

Gateway listen addresses and heartbeat timing.

KeyTypeDefaultDescription
ws_listen_addrString (SocketAddr)"0.0.0.0:9824"IP:port for the WebSocket/HTTP server. Supports IPv4 and IPv6 (bracket form [::1]:9824). The same port serves /v1/orders, /v1/marketdata, /healthz, and /metrics.
fix_listen_addrString (SocketAddr)"0.0.0.0:9823"IP:port for the FIX 4.2 acceptor. Supports IPv4 and IPv6.
fix_heartbeat_secsu6430Seconds between FIX heartbeat messages. Set to 0 to disable outgoing heartbeats. Must be ≥ 0.

Example:

[server]
ws_listen_addr = "127.0.0.1:9824"
fix_listen_addr = "0.0.0.0:9823"
fix_heartbeat_secs = 30

[paths]

Directories for reference data files.

KeyTypeDefaultDescription
instrumentsPathBuf"instruments/"Directory containing .toml instrument definition files. Hot-reloaded via notify.
participantsPathBuf"participants/"Directory containing .toml participant (trader) definition files. Hot-reloaded via notify.

Both paths may be relative (to the working directory) or absolute.

Example:

[paths]
instruments  = "instruments/"
participants = "participants/"

[database]

PostgreSQL connection settings.

KeyTypeDefaultDescription
urlString(none)PostgreSQL connection string. When absent or empty, persistence is disabled (in-memory only). Format: postgres://user:pass@host:port/dbname.
max_connectionsu328Maximum connections in the connection pool. Must be ≥ 1.

Example:

[database]
url = "postgres://nadatrade@localhost:5432/nadatrade"
max_connections = 8

[persist]

Event persistence and snapshot tuning.

KeyTypeDefaultDescription
batch_maxusize500Maximum events to accumulate before flushing to PostgreSQL. Higher values increase throughput but also memory usage and latency.
batch_max_msu6450Maximum milliseconds between flush batches. A flush fires when either batch_max events accumulate or batch_max_ms elapses. Set to 0 to flush every event immediately.
snapshot_every_eventsusize10000Take a full state snapshot every N events. Snapshots accelerate recovery by reducing the number of events that must be replayed.
queue_warn_depthusize5000When the internal event queue reaches this depth, a warning is emitted. Does not block — events continue to accumulate.

Example:

[persist]
batch_max            = 500
batch_max_ms         = 50
snapshot_every_events = 10000
queue_warn_depth     = 100000

[simulation]

SimClock and replay controls.

KeyTypeDefaultDescription
modeString"" (RealTime)Clock driver mode. Valid values: "real_time", "accelerated", "replay". Case-insensitive. An empty string is treated as "real_time".
clock_speedf641.0Time multiplier for accelerated mode. 2.0 = twice as fast, 0.5 = half speed. Ignored in real_time and replay modes. Must be ≥ 0.
sim_startString (ISO 8601)(none)Override the simulation start time. Format: "2026-06-11T00:00:00Z". When omitted, uses the current wall-clock time. Useful for deterministic replay.
replay_feedString (PathBuf)(none)Path to an NDJSON market data replay file. Required when mode = "replay". Each line is a JSON record with market data (trades, quotes).
latency_seedu64(none)Seed for the Box-Muller latency simulator. When omitted, uses system entropy. Set to a fixed value for reproducible latency.

Example:

[simulation]
mode        = "real_time"
clock_speed = 1.0

# Replay mode example:
# mode         = "replay"
# replay_feed  = "data/feed.ndjson"
# sim_start    = "2026-01-02T09:30:00Z"
# latency_seed = 42

Valid modes:

ValueBehavior
"real_time" (or empty)Wall clock drives simulation time 1:1.
"accelerated"Simulation time advances at clock_speed × wall-clock time.
"replay"Simulation time is driven by timestamps from an NDJSON replay feed.

[matching]

Matching engine configuration.

KeyTypeDefaultDescription
book_depth_levelsusize20Maximum price levels visible in the order book snapshot (per side). Deeper levels still exist internally but are not included in market data. Must be ≥ 1.

Example:

[matching]
book_depth_levels = 20

[fix]

FIX 4.2 gateway settings.

KeyTypeDefaultDescription
store_dirString (PathBuf)"data/fix_store"Directory for the per-session FIX message store (append-only journal). Created automatically if it doesn’t exist.
default_roleString"both"Default FIX session role if not specified per-connection. Valid values: "both", "orderentry", "marketdata".
reset_on_logonboolfalseWhen true, resets the message store sequence numbers on every logon. Use only in development.
heartbeat_secsu6430Seconds between FIX heartbeat messages. Must be ≥ 0.
store_capusize1000Maximum messages retained per session in the in-memory store (used for resend requests). Older messages are evicted when the cap is exceeded.

Roles:

ValuePermissions
"both"Session can send orders and receive market data.
"orderentry"Session can only send orders (no market data subscriptions).
"marketdata"Session can only receive market data (no order entry).

Example:

[fix]
store_dir     = "data/fix_store"
default_role  = "both"
reset_on_logon = false
heartbeat_secs = 30
store_cap     = 1000

[tui]

Terminal UI dashboard settings.

KeyTypeDefaultDescription
enabledboolfalseWhen true, launches the ratatui TUI dashboard on startup. The TUI has 5 tabs: Instruments, Order Book, Events, Clock, Ledger.

Example:

[tui]
enabled = true

[logging]

Logging output configuration.

KeyTypeDefaultDescription
levelString"info"Minimum log level. Valid values (case-insensitive): "trace", "debug", "info", "warn", "error".
formatString"pretty"Log output format. Valid values: "pretty" (human-readable, multi-line), "json" (single-line JSON), "compact", "full".

Example:

[logging]
level  = "info"
format = "pretty"

Top-Level Keys

KeyTypeDefaultDescription
ws_jwt_secretString"changeme"HS256 signing secret for WebSocket JWT authentication. Must be changed in production. See below for env: prefix support.

Example:

ws_jwt_secret = "nadatrade-dev-secret-key-change-in-production"

Environment Variable Resolution (env: prefix)

Any config value that accepts a String may use the special env:VARNAME prefix to read the value from an environment variable at config load time. This is resolved after TOML parsing, before the value is passed to the application.

Format:

key = "env:VARIABLE_NAME"

Example:

ws_jwt_secret = "env:NADATRADE_JWT_SECRET"

[database]
url = "env:DATABASE_URL"

When the process loads the config file, a value starting with env: causes the config loader to strip the env: prefix, look up the remaining string as an environment variable name, and replace the value with the variable’s contents.

If the environment variable is not set, the key resolves to an empty string. For keys that are Option<T> (such as database.url), an unset variable resolves to None.

Values that do not start with env: are used as-is with no substitution.

Security considerations:

  • The env: prefix is resolved at startup; changes to environment variables require a restart.
  • Do not commit TOML files containing ws_jwt_secret values to version control. Use env:NADATRADE_JWT_SECRET instead and set the variable in your deployment environment.
