NadaTrade Documentation

Event Catalog

All events emitted by the NadaTrade matching engine, post-trade engine, and clock layer. Every ExchangeEvent variant is persisted to the events table and broadcast to all connected gateways (FIX, WebSocket, TUI).

SequencedEvent wrapper

Before persistence and broadcast, every ExchangeEvent is wrapped in a SequencedEvent envelope.

#![allow(unused)]
fn main() {
pub struct SequencedEvent {
    pub sequence: u64,
    pub event: ExchangeEvent,
}
}
FieldTypeDescription
sequenceu64Monotonically increasing event number across the entire system
eventExchangeEventThe payload variant (see below)

Every ExchangeEvent variant carries its own sim_time (simulation clock time, DateTime<Utc> as epoch milliseconds). The wrapper does not duplicate sim_time — clients read it from the inner event.

JSON envelope example:

{
  "sequence": 12345,
  "event": {
    "event": "trade_printed",
    "trade_id": "b3c1a2d4-...",
    "instrument": "PETR4",
    "qty": "300",
    "price": "38.50",
    "aggressor_side": "buy",
    "buyer_id": "BOT001",
    "seller_id": "BOT002",
    "buyer_order_id": "f5e6d7c8-...",
    "seller_order_id": "a1b2c3d4-...",
    "synthetic": false,
    "sim_time": 1718143200000
  }
}

Enum tag

ExchangeEvent uses serde internally-tagged representation:

#![allow(unused)]
fn main() {
#[serde(rename_all = "snake_case", tag = "event")]
}

Every variant serializes with an "event" field containing the snake_case variant name (e.g. "order_accepted", "trade_printed", "session_state_changed").

Serialization conventions

Rust typeJSON representation
Price, Qty (Decimal)JSON string ("38.50") via rust_decimal::serde::str
OrderId, TradeId (Uuid)JSON string with hyphens ("b3c1a2d4-...")
DateTime<Utc>Epoch milliseconds integer via chrono::serde::ts_milliseconds
Option<Price>String or absent via rust_decimal::serde::str_option + skip_serializing_if
All enums (Side, OrderType, SessionState, …)snake_case string
Vec<(Price, Qty)>Array of ["price_str", "qty_str"] two-element arrays

ExchangeEvent variants

1. OrderAccepted

Fires when a new order passes all pretrade checks and is accepted by the matching engine.

FieldTypeDescription
order_idUuidExchange-assigned order ID
participantStringParticipant ID
instrumentStringInstrument ID
sideSide"buy" or "sell"
order_typeOrderType"limit", "market", "stop", "stop_limit", "market_to_limit", "iceberg"
qtyDecimalOrder quantity (string)
priceOption<Decimal>Limit price (string), absent for market orders
tifTimeInForce"day", "gtc", "gtd" (with timestamp), "ioc", "fok", "at_open", "at_close"
client_order_idStringClient-assigned correlation ID
sim_timeDateTime<Utc>Simulation time (epoch ms)

10. BookUpdated

Fires whenever the order book depth changes — on each new order, fill, cancel, expire, or replace. Emitted at most once per matching engine process cycle per instrument.

FieldTypeDescription
instrumentStringInstrument ID
bidsVec<(Price, Qty)>Ordered list of bid price levels (descending price)
asksVec<(Price, Qty)>Ordered list of ask price levels (ascending price)
sim_timeDateTime<Utc>Simulation time (epoch ms)

Each price level in bids and asks is a two-element array of Decimal strings: [price, qty].

{
  "event": "book_updated",
  "instrument": "PETR4",
  "bids": [
    ["38.49", "500"],
    ["38.48", "1200"],
    ["38.45", "300"]
  ],
  "asks": [
    ["38.51", "700"],
    ["38.55", "400"]
  ],
  "sim_time": 1718143200000
}

11. SessionStateChanged

Fires on every session state transition for an instrument.

FieldTypeDescription
instrumentStringInstrument ID
fromSessionStatePrevious session state
toSessionStateNew session state
sim_timeDateTime<Utc>Simulation time (epoch ms)

SessionState values:

  • closed — No trading, no orders accepted
  • pre_open — Orders accepted for opening auction, no matching
  • opening_auction — Opening auction in progress
  • trading — Continuous trading
  • trading_halt — Trading paused: {"trading_halt": {"reason": "circuit_breaker", "until": null}}. reason is a HaltReason (circuit_breaker, manual_halt, technical_halt). until is an optional epoch ms timestamp.
  • reopening_auction — Reopening auction after halt
  • closing_auction — Closing auction
{
  "event": "session_state_changed",
  "instrument": "PETR4",
  "from": "pre_open",
  "to": "opening_auction",
  "sim_time": 1718143200000
}

Halt example:

{
  "event": "session_state_changed",
  "instrument": "PETR4",
  "from": "trading",
  "to": {
    "trading_halt": {
      "reason": "circuit_breaker",
      "until": null
    }
  },
  "sim_time": 1718143300000
}

Event lifecycle summary

                  ┌──────────────┐
                  │ OrderAccepted │
                  └──────┬───────┘
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
  ┌──────────┐   ┌───────────────┐  ┌────────────┐
  │OrderFilled│   │OrderPartiallyFilled│  │OrderCancelled│
  └──────────┘   └───────────────┘  └────────────┘
         │               │
         │    ┌──────────┘
         ▼    ▼
  ┌──────────────┐
  │ TradePrinted │
  └──────┬───────┘
         │ (T+N days later)
         ▼
  ┌──────────────────┐
  │ ObligationSettled│
  └──────────────────┘

  OrderAccepted → OrderReplaced (amend) → new OrderAccepted on replace
  Limit order with IOC/FOK → OrderExpired if unfilled
  Stop order → StopTriggered (via BookUpdated + TradePrinted on trigger)
