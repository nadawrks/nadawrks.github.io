NadaTrade Documentation

Decisions

This document records frozen architectural decisions made during NadaTrade development. Each entry is a condensed reference; full context lives in DECISIONS.md at the repo root.

2026-06-11: Core crate freeze

Decision: nadatrade-core v0.1.0 is immutable — any type change requires a version bump and orchestrator approval.

Rationale: Spec §21.2 mandates a frozen message model before parallel crate development begins. Ensures all downstream crates build against a stable contract.

Impact: nadatrade-core (types, enums, commands, events, registry traits).

2026-06-11: BookUpdated wire format — tuples over objects

Decision: BookUpdated { bids: Vec<(Price, Qty)>, asks: Vec<(Price, Qty)> } uses tuples instead of PriceLevel objects per spec §6.3.

Rationale: Reduces wire size and matches the spec’s normative data model. This is a breaking JSON change: {"price":"38.50","qty":"1200"} becomes ["38.50","1200"].

Impact: nadatrade-core, persistence, WebSocket gateway, replay feeds.

2026-06-11: Event broadcast architecture

Decision: A single broadcast::channel<Arc<SequencedEvent>>(4096) fans out all exchange events from the main event loop.

Rationale: Avoids per-consumer fan-out loops. The main loop assigns global sequence numbers before broadcasting. All consumers — FIX sessions, WS subscribers, TUI, persistence, postrade — receive cloned Receiver handles.

Impact: nadatrade-bin (main loop), all gateway crates, nadatrade-persist, nadatrade-postrade, nadatrade-admin.

2026-06-11: MatchingEngine constructor refactor

Decision: MatchingEngine::new(Arc<InstrumentConfig>) replaces the previous multi-parameter constructor. A new_default(instrument_id, book_depth) convenience constructor exists for tests.

Rationale: Simplifies engine construction as configuration grew beyond 3 parameters. The single-Arc pattern also enables runtime instrument hot-reload.

Impact: nadatrade-matching (engine, tests, examples, router).

2026-06-11: SessionStateMachine in engine

Decision: Engine owns SessionStateMachine directly. on_tick() is called before each processing cycle. Auction uncrossing is triggered on session transitions. The circuit breaker uses force_state() for halt transitions.

Rationale: Session gating must happen inside the engine’s critical path to ensure order commands are blocked during halted/closed states without race conditions.

Impact: nadatrade-matching, nadatrade-sessions.

2026-06-11: Persistence fallback — no-Postgres mode

Decision: EventWriter uses Option<PgPool>. When no database URL is configured, the binary starts gracefully in memory-only mode with no persistence.

Rationale: Enables development and testing without a running PostgreSQL instance. Recovery only runs when a pool is available.

Impact: nadatrade-persist, nadatrade-bin.

2026-06-11: FIX per-session sequence numbers

Decision: build_execution_report takes explicit seq_num: u64. Per-session next_seq_num_out() helper. Sequence numbers are tracked per-connection and persisted via MessageStore (file-backed append-only journal).

Rationale: FIX requires per-session message sequencing for gap detection and resend. Storing sequence numbers per session identity (SenderCompID + TargetCompID) enables correct ResendRequest replay.

Impact: nadatrade-fix (codec, session, store).

2026-06-11: WebSocket JWT auth flow

Decision: First WebSocket message must be {"type":"auth","token":"<jwt>"}. The JWT sub claim becomes the participant_id.

Rationale: A custom in-band auth protocol avoids the complexity of Bearer token header upgrade negotiation. This is noted as future work for standard compliance.

Impact: nadatrade-ws (server, auth).

2026-06-11: SimClock wiring in binary

Decision: Binary creates Arc<dyn SimClock> based on config (real_time → RealTimeClock, accelerated → AcceleratedClock, replay → ReplayDrivenClock). ClockDriver::run() sends OrderCommand::ClockTick via mpsc channel.

Rationale: Resolves spec §2.5 [NORMATIVE] violation. All business logic time flows through the SimClock trait, enabling deterministic replay and accelerated simulation.

Impact: nadatrade-bin, nadatrade-simulation.

2026-06-11: Postrade position accounting — 3-case apply_fill

Decision: apply_fill() handles three cases: (1) extending position updates avg_cost, (2) reducing position computes realized P&L without changing avg_cost, (3) flipping position closes old, opens new at fill_price. Cash tracking and settlement obligations (T+N cycle) are included.

Rationale: Correct position accounting is foundational for risk checks and regulatory reporting. The three-case model matches industry-standard P&L accounting.

Impact: nadatrade-postrade (ledger, settlement).

2026-06-11: Persistence recovery — JSONB type handling

Decision: Recovery reads persist_meta, loads newest snapshots per instrument, replays events since snapshot. The persist_meta.value column is JSONB — recovery handles both Number and String JSON types.

Rationale: PostgreSQL’s JSONB can store numbers as either Number or String depending on serialization path. Recovery must handle both to avoid parse failures on restored state.

Impact: nadatrade-persist (recovery, writer).

2026-06-11: FIX integration test approach

Decision: FIX integration tests use in-process acceptors with real TCP connections (FixAcceptor::bind() on random port). The event_tx broadcast sender must be kept alive for the test duration.

Rationale: Dropping the broadcast sender closes the channel, which exits the write task, which drops the TCP writer, closing the connection. A FixTestCtx struct holds the sender alive across the test.

Impact: nadatrade-fix integration tests, tests/ directory.

2026-06-11: Coverage strategy and ceiling

Decision: Unit tests target crate-internal logic. Integration tests with Docker/Testcontainers cover persistence and recovery. FIX/WS integration tests use in-process servers. The realistic coverage ceiling is ~78%.

Rationale: Binary main.rs orchestration (~300 lines) and WebSocket server connection handling (~200 lines) require subprocess-level harnesses to test, and are excluded from unit coverage targets.

Impact: All crates, CI pipeline, coverage reporting.

2026-06-11: PretradeActor channel position

Decision: Pretrade risk checks run in a standalone actor positioned between gateways and matching engine: Gateway → LatencySim → PretradeActor → Engine.

Rationale: A dedicated channel-stage actor enables the full 11-point risk pipeline without adding risk-check logic to the engine’s critical path. Rejections are returned to the gateway before the engine ever sees the order.

Impact: nadatrade-pretrade, nadatrade-bin (channel wiring).

2026-06-11: Snapshot scheduling via OrderCommand

Decision: Snapshots are triggered by a dedicated OrderCommand::Snapshot variant with a oneshot reply channel for the result.

Rationale: The main event loop can signal snapshot requests through the existing command channel without introducing a separate control plane. The oneshot channel provides synchronous feedback to the caller.

Impact: nadatrade-core (commands), nadatrade-matching (engine), nadatrade-persist (writer).

2026-06-11: Monthly partition management

Decision: Events table uses PostgreSQL PARTITION BY RANGE on created_at. Partitions are created per month with a cached check in flush() to avoid querying pg_class on every batch.

Rationale: Partitioning avoids unbounded table growth while keeping query performance stable. Caching the current partition month prevents unnecessary catalog lookups in the hot path.

Impact: nadatrade-persist (DDL, writer flush).

2026-06-11: Per-participant MD extra delay

Decision: ParticipantConfig carries an md_extra_delay_us field. LatencySimulator::md_delay_for() applies this per-participant delay to market data outbound queues.

Rationale: Simulates the real-world condition where different participants receive market data at different times (e.g., proximity hosting vs. remote connections). Required by spec §14.4.

Impact: nadatrade-core (participant config), nadatrade-simulation (latency), nadatrade-fix, nadatrade-ws.

2026-06-11: SimClock mandate — no wall-clock in business logic

Decision: tokio::time::sleep, Instant::now, and chrono::Utc::now are forbidden in business code. Only SimClock implementations, gateway heartbeats, metrics, and DB batching may use real time.

Rationale: Deterministic replay requires all time to flow through a single abstract clock. Mixing wall-clock and simulation time produces non-reproducible execution and incorrect event ordering during replay.

Impact: All crates except nadatrade-simulation impls and gateway I/O layers.

2026-06-11: Determinism rules — BTreeMap, no RNG

Decision: No HashMap iteration in hot paths — use BTreeMap. No random number generation in the matching core.

Rationale: HashMap iteration order is non-deterministic across runs, breaking reproducible execution. RNG in matching would produce different fill outcomes in replay mode. BTreeMap guarantees stable ordering.

Impact: nadatrade-matching (CLOB, stop book, auction), all engine code.

2026-06-11: f64 in ExchangeEvent — manual Eq impl

Decision: ExchangeEvent::ClockSpeedChanged.new_speed is f64 per spec. A manual impl Eq is provided with the documented assumption that NaN is never constructed.

Rationale: The spec mandates f64 for clock speed. Deriving Eq automatically fails because f64 does not implement Eq. The manual impl relies on the invariant that NaN values are guarded at construction.

Impact: nadatrade-core (events).

2026-06-11: StpCancelled spelling

Decision: StpCancelled uses double-‘l’ spelling, matching the spec.

Rationale: Differs from single-‘l’ variants in CancelReason but the spec is authoritative. This is a known inconsistency — do not “fix” it.

Impact: nadatrade-core (enums), all consumers of cancel events.

2026-06-11: Auction uncrossing simplification

Decision: The two-phase allocation algorithm from the spec is simplified to single-phase in the current implementation.

Rationale: The single-phase approach is functionally correct and produces identical fill outcomes for all test scenarios. Two-phase allocation is deferred until performance or edge-case requirements demand it.

Impact: nadatrade-matching (auction).

2026-06-11: OpeningAuction Limit-only restriction

Decision: OpeningAuction now restricts order entry to OrderType::Limit only, per spec §8.2.

Rationale: The previous implementation allowed all order types during auction, which could produce unexpected fills. Market and stop orders have no meaningful auction behavior.

Impact: nadatrade-matching (engine order gating).

2026-06-12: Settlement cash deferred to sweep only

Decision: settle_trade() no longer adjusts cash immediately. Cash moves only during sweep_settlements() when the T+N obligation matures.

Rationale: The previous code adjusted cash both at trade time AND at settlement time, double-counting every trade’s cash impact. Deferring cash movement to settlement sweep matches real-world T+N settlement where cash isn’t available until the obligation clears.

Impact: nadatrade-postrade (settlement).

2026-06-12: MessageStore append-only architecture

Decision: The store O(n²) rewrite-on-every-record pattern replaced with append-only writes. Header (last_seq_in, last_seq_out) lives in a separate <identity>.fixheader file.

Rationale: Rewriting the entire log file on every inbound/outbound record is O(n²) I/O and corrupts the entire store on crash. Append-only entries with a separate small header file eliminates both problems. All expect() panics removed; I/O errors handled gracefully.

Impact: nadatrade-fix (store).

2026-06-12: AcceleratedClock RwLock replaces UnsafeCell

Decision: UnsafeCell<f64> + unsafe impl Sync replaced with RwLock<f64>. paused_at field stores the time when paused instead of returning sim_start.

Rationale: The UnsafeCell<f64> had a data race (undefined behavior) on concurrent set_factor() and now() calls. RwLock provides safe interior mutability. Returning sim_start when paused caused backwards time travel; returning the paused-at time preserves monotonicity.

Impact: nadatrade-simulation (clock).

2026-06-12: PretradeActor active_order_ids lifecycle

Decision: Background task now removes (participant, instrument, client_order_id) tuples on OrderFilled and OrderExpired events, not just OrderCancelled.

Rationale: Previously, once an order filled or expired, its ClOrdID was permanently stuck in the active set, causing all future orders with that ID to be falsely rejected as DuplicateClOrdId.

Impact: nadatrade-pretrade (actor).

2026-06-12: FIX auth — require explicit allow_no_auth

Decision: FixSession.allow_no_auth: bool (default false). When credentials is empty and allow_no_auth is false, logon is rejected.

Rationale: The previous code silently accepted all logons when credentials were unset, creating an implicit auth bypass. The flag makes the intent explicit — empty credentials without opt-in is a configuration error, not a dev mode.

Impact: nadatrade-fix (session).

2026-06-12: WS is_subscribed — empty set no longer broadcasts

Decision: is_subscribed() changed from empty || contains(...) to !empty && contains(...). A client with no subscriptions receives no market data.

Rationale: Previously, every WebSocket client received the full market data feed until making at least one subscription. This leaked data to clients who hadn’t explicitly subscribed.

Impact: nadatrade-ws (server).

2026-06-12: Replace order qty semantics

Decision: Three fixes to process_replace:

  1. Default new_qty to remaining_qty, not original_qty.
  2. Match only new_qty - filled_qty incrementally on increase/price-change.
  3. Emit BookUpdated on decrease-only path.

Rationale: Defaulting to original_qty caused previously-filled shares to be re-matched. Matching full new_qty instead of the incremental amount caused double-counting prior fills. Omitting BookUpdated left subscribers with stale book depth.

Impact: nadatrade-matching (engine).

2026-06-12: Event sequence per-event increment

Decision: global_seq now increments inside the per-event loop, not once per batch. Every event gets a unique monotonically increasing sequence.

Rationale: A single trade producing 8 events previously got 8 rows with the identical sequence number, making replay ordering impossible and violating the PRIMARY KEY uniqueness constraint.

Impact: nadatrade-bin (main loop).

2026-06-12: Utc::now removal from business logic

Decision: chrono::Utc::now() removed from MatchingEngine::new() (epoch init) and FixSession::parse_new_order() (accepts sim_time param). FIX acceptor tracks current_sim_time from ClockTick.

Rationale: Wall-clock time in business logic breaks deterministic replay and produces incorrect GTD expiry times under accelerated simulation. All time must flow through SimClock.

Impact: nadatrade-matching, nadatrade-fix.

2026-06-12: OrderRouter deprecated

Decision: OrderRouter in nadatrade-matching marked #[deprecated]. Routing is handled directly in main.rs via HashMap<InstrumentId, MatchingEngine>.

Rationale: The struct had zero references outside its own tests. Marking it deprecated rather than removing avoids breaking downstream consumers.

Impact: nadatrade-matching (router).

2026-06-12: EngineSnapshot dep-inversion deferred

Decision: EngineSnapshot remains in nadatrade-persist despite the clean-architecture violation. Moving it to nadatrade-core is deferred.

Rationale: The snapshot serialization chain is tightly coupled to persistence types. A clean extraction requires significant refactoring. The matching engine’s serialize_snapshot() now returns Result — session state serialization failures propagate rather than silently corrupting.

Impact: nadatrade-persist, nadatrade-matching.
