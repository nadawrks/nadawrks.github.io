NadaTrade Documentation

TUI Dashboard

The NadaTrade terminal UI (built on [ratatui] + [crossterm]) provides a real-time dashboard into the exchange. It displays instrument state, order books, event logs, clock controls, and ledger data — all updated live from the same broadcast channel the rest of the system consumes.

Launch

Embedded mode — Set [tui] enabled = true in your config to start the TUI inside the main binary process:

[tui]
enabled = true

cargo run -p nadatrade-bin -- --config config/nadatrade.toml

When enabled is set, main.rs spawns the TUI on a dedicated std::thread before entering the main event loop. It clones the gateway_cmd_tx sender and subscribes to the event_tx broadcast channel, so every SequencedEvent flowing through the system is mirrored to the TUI.

Standalone mode — Run the TUI crate directly. It connects to the broadcast channel via the same process (no separate socket — the TUI runs in-process):

cargo run -p nadatrade-admin

The TUI runs until you press q or Esc. Exiting the TUI does not stop the exchange — it only detaches the visual dashboard. You can restart it at any time.

Levels display price (right-aligned, 12-width) and quantity (right-aligned for bids, left-aligned for asks). When one side has fewer levels than the other, the remaining rows are blank.

The Order Book tab populates from BookUpdated events. If no events have arrived yet, the display shows a placeholder message.

Data is preserved in a HashMap<String, OrderBookData> keyed by instrument ID, so switching instruments does not lose state.

Note on sim_time extraction: The TUI updates sim_info.last_sim_time from the sim_time field present on every ExchangeEvent variant. It reads the timestamp from whichever event arrived most recently, so the clock display reflects the event stream’s view of time — not wall-clock time.

The sim_time is formatted as %H:%M:%S (hours:minutes:seconds). Sub-second precision is not displayed in the TUI.

Architecture Notes

Event loop: The TUI runs a while app.running loop that:

  1. Draws the current frame via render()
  2. Polls for keyboard input with a 50 ms timeout (event::poll)
  3. Attempts a non-blocking read from the broadcast channel (try_recv)
  4. On Lagged(n), emits a ⚠ DROPPED N events log entry
  5. On Closed, logs a final message and the loop exits naturally on the next q press

Data structures: The App struct keeps all state in memory:

  • instruments: HashMap<String, InstrumentRow> — keyed by symbol
  • order_books: HashMap<String, OrderBookData> — keyed by symbol, contains bids and asks Vec<(Price, Qty)>
  • event_log: Vec<String> — capped at 200 entries, drained from the front
  • sim_info: SimInfo — clock speed, paused flag, last sim_time, session state
  • ledger_data: HashMap<String, LedgerRow> — keyed by participant ID

All state is reconstructed entirely from the event stream. There is no persistent on-disk state for the TUI — restarting it re-subscribes to the broadcast and re-populates from incoming events.

Thread model: The TUI runs on a std::thread (not a tokio task) because crossterm raw-mode terminal handling requires blocking synchronous I/O on the main thread. It owns the terminal handle, enters alternate screen mode on start, and restores the terminal on exit.

Sim time propagation: Every ExchangeEvent variant carries a sim_time: DateTime<Utc> field. The TUI extracts this via event_sim_time() and updates the clock display regardless of which event variant arrived. This means the displayed time advances as the event stream flows — it does not tick independently between events.

Troubleshooting

TUI not appearing: Verify [tui] enabled = true in config. If running standalone via cargo run -p nadatrade-admin, ensure the main binary is running and publishing events to the broadcast channel.

Blank tabs: Tabs populate lazily from events. If no events have been emitted (e.g., no orders, no session transitions), tabs will show placeholder text. Place an order to verify the pipeline.

Dropped events: The ⚠ DROPPED N events message means the terminal render loop is too slow for the event rate. This is normal during high-frequency bursts (e.g., replay mode at high speed). The TUI intentionally trades completeness for responsiveness.

Terminal not restored on exit: The TUI registers disable_raw_mode() and LeaveAlternateScreen in both the success and error paths. If the process is killed with SIGKILL (not SIGTERM/CTRL-C), the terminal may remain in raw mode. Run reset or stty sane to recover.

When enabled = false (default), the TUI is not spawned and the main binary runs headless. You can still launch the TUI separately via cargo run -p nadatrade-admin, but it must connect to a running nadatrade-bin process that shares the broadcast channel — which, in practice, means running it in-process.
