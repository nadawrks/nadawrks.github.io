NadaTrade Documentation

Sessions

Each NadaTrade instrument runs an independent session state machine modelled after real exchange phases: pre-open, auctions, continuous trading, halts, and close. The machine is driven exclusively by SimClock ticks and scenario/circuit-breaker events, keeping all book mutations single-threaded on the matching actor.

Session Types

Every instrument declares one of two session types in its TOML config:

Session typeDescription
continuous_24x7Always Trading; never opens, closes, or auctions. Only TradingHalt (scenario/circuit-breaker) can interrupt it.
session_basedFollows a daily schedule: PreOpen → OpeningAuction → Trading → ClosingAuction → Closed.

State Machine — 7 States

StateDescription
ClosedOutside trading hours. No new orders accepted; cancels/replaces rejected. Books are empty if end-of-day cleanup ran.
PreOpenOrder-entry only. Limit, Stop, StopLimit, and Iceberg orders (with Day, GTC, GTD, or AtOpen TIF) are collected into the book. No matching occurs. Market, IOC, and FOK orders are rejected.
OpeningAuctionAuction collection phase. Only Limit orders (Day, GTC, GTD, AtOpen) are accepted. At the end of the auction, uncross() determines the opening price using the call-market algorithm and generates fill events.
TradingContinuous matching. All valid order-type × TIF combinations are accepted. Matching, stop triggers, and circuit-breaker checks run on every new order.
TradingHalt { reason, until }Trading is suspended. The reason is one of CircuitBreaker, ManualHalt, or TechnicalHalt; until is the UTC timestamp when the halt may expire (if a duration was set). New orders are rejected; cancels and replaces are still accepted.
ReopeningAuctionOccurs after a TradingHalt expires with auto_reopen = true. Only Limit orders (Day, GTC, GTD) are accepted. The uncross price becomes the new reference price, re-arming the price band.
ClosingAuctionEnd-of-day auction collection. Only Limit orders (Day, GTC, GTD, AtClose) are accepted. After uncross, the state transitions to Closed and end-of-day cleanup runs.

Note: A Suspended state is not currently implemented. Instruments that are delisted transition directly to Closed.

Schedule-Driven Transitions

SessionSchedule::compute() builds a per-day schedule from the instrument’s SessionConfig, using timezone-aware NaiveTime fields and a trading_days allow-list.

Typical trading day (Sao Paulo time)

TimeState
09:45PreOpen begins
09:55OpeningAuction begins (continuous_start minus auction_duration)
10:00Auction uncross → Trading begins
17:30ClosingAuction begins
17:40Closing uncross → Closed

On each ClockTick, SessionStateMachine::on_tick() checks whether sim_time has crossed the next scheduled boundary. If it has, the machine transitions to the next state and the matching engine performs any associated work (auction uncross, EOD cleanup).

Timings for the schedule fields:

Config fieldDefaultDescription
pre_open_start—NaiveTime when PreOpen begins.
continuous_start—NaiveTime when continuous trading begins.
opening_auction_duration_secs300Seconds before continuous_start when the opening auction phase starts.
closing_auction_start—NaiveTime when the closing auction begins.
closing_auction_duration_secs600Duration of the closing auction in seconds.
reopening_auction_duration_secs300Duration of the reopening auction after a halt expires.
timezoneAmerica/Sao_PauloIANA timezone for interpreting NaiveTime fields.

Example config

[instruments.PETR4.session]
type = "session_based"
pre_open_start = "09:45:00"
continuous_start = "10:00:00"
opening_auction_duration_secs = 300
closing_auction_start = "17:30:00"
closing_auction_duration_secs = 600
timezone = "America/Sao_Paulo"

Event-Driven Transitions

Circuit Breaker

The circuit breaker fires after any trade print in Trading when |last_trade − reference_price| / reference_price > price_band. The flow depends on configuration:

  • auto_reopen = true with halt_duration_secs set: Trading → TradingHalt { reason: CircuitBreaker, until } → (halt expires) → ReopeningAuction → (auction uncross) → Trading. The uncross price becomes the new reference price.

  • auto_reopen = false or no duration: Trading → TradingHalt { reason: CircuitBreaker, until: None }. The halt persists until a manual resume via ScenarioEvent::ResumeInstrument.

Orders remain in the book during a halt; cancels and replaces are allowed.

Manual Halt

A ScenarioEvent::HaltInstrument or an admin command triggers:

Trading → TradingHalt { reason: ManualHalt, until }

Manual Resume

Per design decision, ScenarioEvent::ResumeInstrument (or an admin command) transitions directly from TradingHalt to Trading without a reopening auction. This lets operators resume trading immediately after investigating a halt.

Order Gating

Which order types are accepted depends on the current session state:

StateNew ordersCancelsReplacesMatching
ClosedNone (SessionNotAcceptingOrders)None (SessionNotAcceptingCancels)None—
PreOpenLimit, Stop, StopLimit, Iceberg (Day, GTC, GTD, AtOpen)YesYes (no re-match)None — collect only
OpeningAuctionLimit (Day, GTC, GTD, AtOpen)YesYes (no re-match)None — collect; uncross at end
TradingAll valid type × TIF combosYesYesContinuous
TradingHaltNone (InstrumentHalted)YesYes (no re-match)None
ReopeningAuctionLimit (Day, GTC, GTD)YesYes (no re-match)None — collect; uncross at end
ClosingAuctionLimit (Day, GTC, GTD, AtClose)YesYes (no re-match)None — collect; uncross at end
  • IOC, FOK, Market orders are only accepted in Trading.
  • AtOpen orders are accepted in PreOpen and OpeningAuction; AtClose orders in ClosingAuction.
  • Stops submitted during PreOpen rest in the Stop Book and are first evaluated against the opening auction print.

Trading Calendar

The trading_days list in SessionConfig controls which days the schedule applies:

trading_days = ["Mon", "Tue", "Wed", "Thu", "Fri"]
  • "Mon-Fri" (weekdays only) — typical for equity exchanges.
  • "Mon-Sun" — all days, including weekends.
  • An empty list or ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"] — every day is a trading day.
  • On non-trading days, SessionSchedule::compute() returns all None values and the state remains Closed.

A holiday calendar is not currently implemented (future work).

End-of-Day Cleanup

When the state transitions to Closed (after the closing uncross), the following runs in order:

  1. AtClose remainders — unfilled AtClose orders are expired with ExpireReason::AuctionUnfilled (by the uncross step itself).
  2. Day orders — all Day orders in the CLOB and Stop Book are cancelled with CancelReason::SessionEnd.
  3. GTD expiry — GTD orders whose expiry_date ≤ today are expired with ExpireReason::GtdExpired. Stop Book GTD stops are also purged.
  4. GTC EOD purge — GTC orders from participants with gtc_eod_purge = true in their ParticipantConfig are expired with ExpireReason::DayEndGtc.
  5. Remaining GTC/GTD orders persist in the book across Closed into the next PreOpen.

On OpeningAuction → Trading: AtOpen remainders are expired (AuctionUnfilled).

GTD and Day expiries are driven by SimClock ticks — the matching actor checks every sim-time second whether any GTD timestamps have elapsed.

Circuit Breaker Configuration

[instruments.PETR4.circuit_breaker]
enabled = true
halt_duration_secs = 300
auto_reopen = true
FieldDefaultDescription
enabledfalseWhether the circuit breaker is active for this instrument.
halt_duration_secsNoneHow long the halt lasts before automatic transition.
auto_reopenfalseIf true, transitions to ReopeningAuction after the halt expires. If false, the halt persists until a manual resume.

The trigger threshold is the instrument’s price_band — the maximum allowed deviation from reference_price as a decimal fraction. When breached, the circuit breaker fires and a SessionStateChanged event is emitted with the halt reason and until timestamp.

GTD/Day Expiry

GTD and Day expiry is SimClock-tick-driven (not tokio timers), so it behaves correctly under acceleration and replay. On every ClockTick, the matching actor checks:

  • GTD orders — if sim_time >= expiry_timestamp, the order expires (ExpireReason::GtdExpired).
  • Untriggered GTD stops — stops with GTD TIF that never triggered are expired (ExpireReason::StopNeverTriggered).

Expiry resolution is 1 sim-second.

Session State Change Events

Every transition emits ExchangeEvent::SessionStateChanged:

{
  "type": "session_state_changed",
  "instrument": "PETR4",
  "from": "trading",
  "to": { "trading_halt": { "reason": "circuit_breaker", "until": 1718236800000 } },
  "sim_time": 1718236500000
}

These events are broadcast to all gateways and the event store, allowing downstream consumers (TUI, persistence, metrics) to track state without polling.
